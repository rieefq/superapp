## GLOBAL SHELL (src/app/shell/**) — functional requirements
Use the names, placement, dimensions and visual treatment from docs/DESIGN.md; this list is what must WORK.

1. Navigation rail: Home + grouped workspaces from src/app/registry.ts (MANIFESTS, NAV_GROUPS), system group at the bottom, user menu. Active state from the route; labels/tooltips; collapsed/expanded state persisted; badges where meaningful (e.g. pending approvals on Agents, working count). Keyboard: chord shortcuts from each manifest's `chord` (e.g. G then C → Chat) handled globally (ignored while typing in inputs).
2. Top bar: location (scope › workspace › current item title, resolved via useEntity when the route has an entity id), the command trigger, the live-runs surface, notifications/approvals, context panel toggle, theme toggle, user menu (profile name, settings, keyboard shortcuts, reset demo world (confirm), about/honesty).
3. Project scope switcher: all projects (hue/icon) + "All work"; changing scope updates useContextStore.scopeProjectId and every workspace filters by it (they read useScope()). Clearly visible current scope. Keyboard reachable.
4. Command center (⌘K / Ctrl+K, also `/` when not typing): one input that (a) searches everything via the real search service (grouped by kind with highlighted snippets; Enter opens via entityRoute), (b) navigates to workspaces, (c) runs commands contributed by workspace manifests (`manifest.commands(ctx)`) and global commands (New chat, New investigation, New coding session, New agent, New workflow, New task, New note, Upload to knowledge, Switch scope, Toggle theme, Open settings sections, Approve next approval…), (d) launches work by intent: when the query reads like a request, the top row offers "Ask AI: …" plus the detected intent from detectIntent ("Research: …", "Delegate to <agent>: …", "Build in <repo>: …", "Automate: …", "Create image: …") which call the same core services as Home (sendMessage, createInvestigation, createSession, runAgent, createWorkflow, generateAsset) and navigate to the result. Fuzzy matching on titles/keywords; recent items when empty; keyboard navigation (↑↓, Enter, Esc, Tab to switch mode chips); sub-pages for multi-step commands (e.g. choose agent → type instruction). Accessible (combobox/listbox roles, aria-activedescendant).
5. Live runs surface: always-visible indicator of active runs (count + pulse) and pending approvals; expands to a panel listing active runs (agent identity, title, current step, progress, elapsed; click → entityRoute) and pending approvals (ApprovalCard compact: approve/reject inline with optional note); empty state; updates live.
6. Inbox / notifications: list from useNotifications (grouped by day, tone icons, entity link), mark read on open/click, mark all read, clear; unread badge. New notifications also appear as toasts (settings.notifications.toasts) with a link action — but approvals requested are prominent (they are interrupts).
7. Context panel: what the AI currently has in context — scope project (goal, instructions summary, pinned project memory), pinned items (useContextStore.pinned) as entity chips with remove, add via search picker, clear; "suggested for this view" (the entity on screen + its connections from useConnections) with one-click pin; explanation of how context is used. Pin/unpin actions exist on entities across the app (shared PinButton).
8. Toasts and confirm dialogs: global hosts mounted once (imperative toast() and confirm() APIs from the UI kit).
9. Responsive: below ~768px the rail becomes a bottom tab bar (Home, Chat, Code, Agents, More → sheet with every workspace), top bar compresses (scope + command button + live runs + inbox), panels become sheets. Tablet: rail collapsed by default. No horizontal page scroll at 360px.
10. App readiness: the shell root renders `data-app-ready="true"` once mounted (e2e relies on it). Route-level loading skeleton and error boundary per workspace (errors show a friendly panel with Retry, not a blank page). Page title updates per route (document.title = "<Item> · <Workspace> · Atrium").
11. Workspace transition: subtle content transition on workspace change (respect reduced motion).
12. Keyboard shortcuts registry (src/app/shortcuts.ts): central list used by the handler, the shortcuts help dialog (`?`) and Settings.

## SHARED ACTION COMPONENTS + HOME (src/app/components/**, src/workspaces/home/**)
Connected, reusable building blocks every workspace uses — build them once, well:
- Composer: autosize textarea, Enter to submit (Shift+Enter newline), attachments (picker, drag-drop, paste; real FileReader text extraction and image thumbnails → Attachment objects), context chips (removable), `@` mention picker (search-backed; adds EntityRefs), `/` slash command menu (configurable per host), model picker slot, submit/stop states, disabled + helper text states, keyboard accessible.
- ModelPicker (useModels: availability, reason, link to integrations; Simulated badge on simulator models; shows pricing per MTok for live models).
- Pickers: ProjectPicker, AgentPicker (identity + live status), RepoPicker, CollectionPicker, EntityPicker (search any kinds) — popover/combobox style, keyboard friendly.
- HandoffMenu ("Send to…"/"Turn into…"): for any EntityRef: Task, Research, Agent run, Code session, Knowledge note, Studio asset, Chat (discuss) — opens a small prefilled dialog (describeSource) then calls core/services/handoff, toasts with a link, navigates optionally.
- PinButton (toggle context pin for an EntityRef), ConnectionsList (useConnections → grouped entity chips with relation labels), ProvenanceFooter (model · Simulated/Live · tokens · cost · duration; consistent everywhere AI output appears), SimNotice (explains simulation where needed).
- RunPanel (connected): given runId → header + live RunTimeline + approvals + outputs + controls (pause/resume/cancel/retry) — used by Agents, Code, Research, Workflows, Studio.
HOME (/): intent-first, not a dashboard:
- Greeting in the display face with the user's name (settings.profile.name) and time of day, plus a live one-line state summary computed from data ("3 agents working · 2 approvals need you · 4 tasks due today").
- Intent composer (Composer) with mode chips Ask · Research · Build · Delegate · Automate · Create; detectIntent suggests a mode as you type (non-intrusive, Tab to accept); scope chip; submit routes: Ask → sendMessage → /chat/:id; Research → createInvestigation → /research/:id; Build → repo (scope project's repo or demo) → createSession → /code/:id; Delegate → agent (best match by capabilities, changeable) → runAgent → /agents/:id?run=…; Automate → createWorkflow draft from the text (name + trigger guess + nodes) → /workflows/:id; Create → kind from text → generateAsset → /studio/:id.
- Needs you: pending approvals (inline approve/reject), failed runs in the last 24h (retry / open), overdue tasks (open / complete), integration errors (reconnect) — each actionable; calm empty state when nothing needs you.
- In motion: active runs with live step + progress + agent identity.
- Pick up where you left off: recent threads, sessions, investigations, knowledge, assets, workflows (mixed, by updatedAt).
- Today: my tasks due today/this week, upcoming milestones; rule-based (not AI) suggestions from workspace state ("Investigation X is ready for review", "Session Y has changes to review").
- Respects scope; responsive single column on mobile.
E2E (e2e/home.spec.ts, e2e/shell.spec.ts): home renders with greeting, Needs you lists the 2 seeded approvals, approving one removes it; Ask from Home lands in /chat with a streaming answer; Research mode creates an investigation; ⌘K finds "Atlas Lumen PRD" and opens it; command "New chat" works; scope switcher filters Chat threads; live runs panel shows active runs; notification badge + mark all read; mobile viewport shows bottom tab bar and no horizontal scroll.
